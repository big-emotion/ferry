## 2. What Went Well

**Spec discipline paid off.** PRD → architecture → epics → per-story acceptance criteria meant implementation was a translation exercise, not a discovery exercise. The implementation-readiness report flagged **zero critical violations** before story execution began — that is the upstream win.

**Pre-reserved extension points.** Epic 1's state schema explicitly reserved interrupt/override transition slots for Epic 7, and Epic 4 fell back gracefully on missing `state.touch_paths` from Epic 3. Epic 7 (Human Control & Override) landed as an addition, not a retrofit. This was a planning decision that aged well.

**Atomic story scope.** Each story shipped a single capability, fully tested, with a `feat(<area>): …` commit pattern. The git log reads as a clean delivery sequence (e.g. `5-1`, `5-2`, `5-3`, `5-4` for Reviewer; `6-1` through `6-5` for Iterator). No stories were re-opened after `done`.

**Deferred-work hygiene.** `deferred-work.md` captured every cross-story dependency the Reviewer flagged (W1–W6 from 1-2/1-3, six items from 1-5, etc.) with explicit forward-pointers ("will be wired in Story 3.1+"). This kept reviewers from re-flagging the same issues round after round.

**Schema-validated state.** `.ferry/state.json` validated against `state.v1.schema.json` on every read AND write, with atomic `tmp → rename`. State integrity is mechanically enforced, not relied on by convention.

**Idempotency baked in.** Every external write is prefixed with `[ferry:<role>:<run-id>]` and ULID-ordered for supersession. The dedupe-via-Issue-comment trick is unusual and works because GHA is the only writer.

## 3. What Was Hard / What Hurt

**The "deferred to Story X.Y" pattern accumulated debt.** `deferred-work.md` contains a real backlog: synthetic `start_ms: github.run_id` produces a 55-year `duration_ms`, `jiraCommentTemplate` placeholders never substituted (injection risk noted), `npm ci` cold-cache failures in the audit composite action. These were correctly deferred at review time — but several were tagged "fix in Story 3.1+ / 4.1+" and need a verification pass to confirm they actually got wired.

**Reviewer feedback was not always closed.** Items like the `FerryError.context` JSON-injection risk in `src/lib/error-taxonomy/index.ts:12` are flagged "caller responsibility" — a deferral pattern that only works if the caller actually sanitises. No automated check enforces this.

**No end-to-end runtime test.** Every story has unit tests (`vitest`) and AJV schema validation, but Ferry has not yet been exercised against a real Jira webhook + GitHub Actions runner pair. The CI suite proves the code compiles and units pass; it does not prove the dispatch flow works.

**Solo + AI velocity created a "ship-and-forget" risk.** 41 stories landed without a single intermediate retro. Patterns that should have surfaced earlier (e.g. the placeholder-substitution responsibility convention) were re-encountered across multiple stories. A retro every 3 epics would have caught this once instead of repeatedly.

**TL;DR enforcement (Epic 9) is structural, not semantic.** FR55/FR56 enforce the *shape* of the TL;DR block (six fields, order, length). Nothing checks that "Risk: low" actually corresponds to a low-risk change. This is a known limitation but worth flagging — humans will learn to trust the badge faster than the reality justifies.

## 4. Surprises / Non-Obvious Lessons

**Audit-via-Issue-comment is load-bearing.** Dedupe uses `[ferry:dedupe] <eventId>` comments on the canonical audit Issue. This avoids any owned database, which is great — but it also means **the audit Issue is now a critical path dependency**. If it is accidentally locked, archived, or hits GitHub's per-issue comment limits, dedupe fails open. Worth a guard.

**Schema-loading via `createRequire` is a workaround, not a pattern.** `src/lib/envelope/validate.ts` uses `createRequire` to bypass TypeScript NodeNext subpath restrictions on `ajv/dist/2020`. It works, but it is the kind of thing that breaks on a TS or AJV major bump (ref: PR #20 already had to pin `types: [node]` for TS 6 + `@types/node` 25).

**The 3-iteration cap is doing more work than expected.** Epic 6's resurgent-finding detection (story 6-2) catches the case where the Iterator "fixes" a finding that returns with the same fingerprint — it escalates immediately rather than waiting for the cap. This is the right behaviour, but it means the 3-cap is mostly a backstop, not the primary loop-breaker. Document this.

**Critical-label model routing (story 4-3) is the only place model identity changes mid-pipeline.** Worth flagging in operator docs — when a ticket flips between non-critical and critical, cost telemetry will show a step change in token cost that is not a regression.

## 7. Process Reflections (Solo + AI workflow)

- **The BMad spec → epics → stories pipeline worked.** The implementation-readiness report's zero critical violations is the strongest signal. Keep it.
- **Doing all 9 epics without a retro was too long.** Cadence: retro every 3 epics, or at any "platform shift" (e.g. moving from Epic 6 closed-loop to Epic 7 human-override changed the mental model — would have been a natural retro point).
- **Reviewer's "deferred-work.md" pattern is excellent**, but needs a closeout step. Without one, deferrals become silent.
- **The `feat(<area>): …` commit convention paid off** for both git history readability and for the eventual TL;DR block enforcement in Epic 9.
